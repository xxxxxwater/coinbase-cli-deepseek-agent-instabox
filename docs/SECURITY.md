# 安全模型：这套东西能挡住什么，挡不住什么

这份文档存在的理由：这套栈让一个 LLM agent 能真的动钱。凡是这种系统，
最危险的不是"没有防护"，而是**以为有防护**。所以这里把边界写清楚，
包括那些明确挡不住的情况。

## 一、资产与最坏情况

| 资产 | 最坏情况 | 现状 |
|---|---|---|
| CDP API 私钥 | 泄露 = 别人能以你的名义下单/转账 | 落在 `600` 文件里（见第四节） |
| 交易权限 | 未授权下单、把余额转走 | key 上限定组合与权限范围；`transfer` 需要额外勾选 |
| 服务器 shell | 对话即 shell（Telegram 中继器） | 单 chat 白名单 + 配置 600 |
| 审计记录 | 事后说不清发生了什么 | `journal.jsonl` 只追加、`0600` |

## 二、谁能触发下单

有三条路，三条都要过闸门才安全：

1. **`cb-trade.sh`** —— 脚本层。闸门在预览之前，被拒是 `exit 4`。
2. **`coinbase orders create …`（shell 直连）** —— 由二进制守卫拦。
3. **`coinbase mcp`（agent 真正的路）** —— 由 MCP 代理审 `tools/call`。

第 2、3 条能存在，是因为 agent 会自己拼命令。提示词里写"别超过 100 美元"
是劝告；写在守卫里是闸门。

### 守卫怎么判断

- **kill switch**：`<配置目录>/KILL` 存在 → 拒绝一切下单（`exit 4`）。
- **白名单**：`allowed_products` 非空时，只允许列表里的产品。
- **认不出来就拒**（`exit 78`）：白名单开着却解析不 product_id、找不到风控库、
  找不到 MCP 代理 —— 全部按拒绝处理。"判断不了"不等于"放行"。

### MCP 路径的额外规则

- 只读工具（查价、查余额、列订单）原样透传，否则 agent 连行情都查不了。
- 会动钱的工具先算名义金额：`quote_size` → 直接用；`base_size` → 乘现价；
  两者都没有 → **拒绝**（算不出来不等于 0）。
- 被拒时回一个同 id 的 JSON-RPC `error`，真 server 收不到这条请求。

## 三、明确挡不住的事

写出来是为了让你知道该在哪里停手：

1. **守卫被换掉就没了。** 有 sudo 的人可以直接 `mv` 回真二进制。
   守卫防的是 agent 手滑/被诱导，不是防有 root 的攻击者。开机自检能发现
   "被 npm 覆盖"这一种情况并装回去，但发现不了"有人故意拆掉"。
2. **金额限额只在 `cb-trade.sh` 与 MCP 代理里生效。** 有人手工拼一条
   `coinbase orders create quote_size=99999`，守卫只查 kill switch 和白名单，
   **不查单笔上限**（守卫读不到脚本层的限额配置就按放行处理）。要连这个也堵，
   得让守卫也读风控配置 —— 目前没做，因为那会让"守卫坏了"变成"完全不能用"。
3. **私钥是明文存在磁盘上的**（第四节）。能读这个文件的人不需要绕过任何闸门。
4. **Telegram 中继器用的是 `--dangerously-skip-permissions`。** 谁能给那个
   bot 发消息，谁就能在服务器上执行命令。白名单只有一个 chat id，但答案是这个
   通道本身就是高权限的。
5. **交易对手风险、Coinbase 侧的风控**不在这里，也不该在这里。

## 四、私钥为什么是明文的

无头机器上装 `gnome-keyring` 之后，`secret-tool store` 会**永久挂死**
（不是报错，是等一个永远不会来的输入）。比报错更糟：你的 `coinbase env`
从此没有输出，看起来像网络卡了。

所以这里用 CLI 支持的 `--allow-plaintext-secrets`，把 key 写在
`~/.config/coinbase/config.json`，权限 `600`。

判断依据：单用户沙箱里，空口令的 keyring 提供的保护等级约等于 `600` 文件
（同一用户读得到），却多了一个"重启后 keyring 没起来"的失效模式。
真正的隔离应该靠机器边界，不是靠同一用户下的加密。

如果你的机器**不是**单用户，或者上面跑着别人的进程，这个取舍就不成立 ——
用真 keyring，或者把整个环境放进一台专用机器。

## 五、审计能做到什么

`journal.jsonl` 每行一条：`ts` / `epoch` / `day` / `event` / `product` / `side` /
`type` / `notional` / `result` / `reason`。

- 只追加、`0600`、写入失败会往 stderr 大声警告（静默丢记录比少拒一笔更糟）。
- `cb-risk.sh report` 汇总成"这周被拒了几次、为什么、拒在哪个产品上"。
- **金额只算成功提交**，**笔数算所有尝试**（含失败）—— 失败的单子同样在打
  Coinbase 的接口，只在成功时限流等于没限流。

## 六、最小暴露清单

要降低风险，按这个顺序做：

1. CDP key 上只勾需要的权限（View / Trade / Transfer 逐项看），
   并设 IP allowlist —— 这台机器出网固定，白名单是最省事的一道墙。
2. `cb-risk.sh set max_single_trade_usd 100` + `max_orders_per_hour 6`，
   不设当日上限的话，至少单笔和频率有个底。
3. `install.sh --guard`，装完跑 `cb-doctor.sh` 确认 `guard.on` 与 `risk.limits`。
4. 不用时 `cb-risk.sh kill`（`touch KILL`），比改配置更不容易忘。
5. 定期 `cb-risk.sh report --days 7` 看一眼有没有你没下的单。
